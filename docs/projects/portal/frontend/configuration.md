# Portal frontend configuration

Production runtime settings are generated by the container entrypoint and
served at `/config.json`. The browser fetches this file before initializing
Vue or OIDC. The container merges built-in defaults, an optional JSON file,
then explicitly provided environment variables. `PORTAL_CONFIG_FILE` selects
the file path. Vite development variables are separate and are not read by the
production container.

## Production runtime settings

### `PORTAL_CONFIG_FILE`

**Optional:** Yes.
**Default:** `/etc/portal/config.json`.

Selects the mounted JSON configuration file. A missing file is allowed; the
container still requires the OIDC authority and client ID after environment
overrides are applied.

### `PORTAL_MANAGEMENT_DISPLAY_NAME`

**Optional:** Yes.
**Default:** `Portal`.

Sets the name shown in the management application. Its JSON field is
`managementDisplayName`.

### `PORTAL_OIDC_AUTHORITY`

**Optional:** No for production sign-in.
**Default:** Empty.

OIDC authority used for provider discovery and browser sign-in. Its JSON field
is `oidcAuthority`. It must identify the issuer that the backend validates.

### `PORTAL_OIDC_CLIENT_ID`

**Optional:** No for production sign-in.
**Default:** Empty.

Public browser client identifier registered with the OIDC provider. Its JSON
field is `oidcClientId`. The client uses Authorization Code with PKCE and does
not store a client secret.

### `PORTAL_ACCOUNT_MANAGEMENT_URL`

**Optional:** Yes.
**Default:** Empty.

Optional account-management destination. Its JSON field is
`accountManagementUrl`. When empty, the app derives the Keycloak account
console URL from the OIDC authority.

### `PORTAL_API_BASE_URL`

**Optional:** Yes.
**Default:** `/api`.

Base path or URL the browser uses for backend requests. Its JSON field is
`apiBaseUrl`. A usual deployment routes this path through the management origin
to the backend.

The JSON file must be an object containing only the five fields above, with
string values. The display name, authority, client ID, and API base URL must be
non-empty after merging. Invalid JSON, unknown fields, or missing required
values cause the container to exit. These settings are sent to the browser and
must not contain secrets.

## Vite development settings

These variables are read by Vite for local development and builds. The
`.env.example` file shows example values; it is not production container
configuration.

### `VITE_MANAGEMENT_DISPLAY_NAME`

**Optional:** Yes.
**Default:** `Portal`.

Sets the management name during Vite development and local builds.

### `VITE_OIDC_AUTHORITY`

**Optional:** Yes.
**Default:** Empty.

OIDC authority for normal local sign-in. It is not required while the frontend
mock is active.

### `VITE_OIDC_CLIENT_ID`

**Optional:** Yes.
**Default:** Empty.

Public OIDC client identifier for normal local sign-in. It is not required
while the frontend mock is active.

### `VITE_ACCOUNT_MANAGEMENT_URL`

**Optional:** Yes.
**Default:** Empty.

Optional account-management URL. When empty, the app derives the account
console URL from the OIDC authority.

### `VITE_API_BASE_URL`

**Optional:** Yes.
**Default:** `/api`.

Base path or URL used for API requests in Vite development.

### `VITE_API_PROXY_TARGET`

**Optional:** Yes.
**Default:** `http://127.0.0.1:5000`.

Target for Vite's `/api` development-server proxy, usually the local Portal
backend. This does not configure a production reverse proxy.

### `VITE_PORTAL_DEV_MODE`

**Optional:** Yes.
**Default:** `false`.

Enables frontend-only mock sign-in and preview UI under the Vite development
server. This mock does not make backend requests.

### `VITE_PORTAL_BACKEND_PREVIEW`

**Optional:** Yes.
**Default:** `false`.

Uses the backend preview identity endpoints when `VITE_PORTAL_DEV_MODE` is
also enabled. The backend must independently run its guarded preview mode.
Neither preview setting activates in production builds.
